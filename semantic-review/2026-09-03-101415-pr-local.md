# Standard ERP quotation document modal

The quotation editor moves from an inline decorative shell to a standard Ant Design document modal with a fixed footer and separate product browser. Customer targeting, product and rate editing, authoritative preview-before-create, server totals, close/reset, and submit loading remain connected to their existing handlers. Walk-in browsing now requires the same nonblank customer name already required at submission. **Watch for: [confirmed]** the new visual labels are not programmatically associated with their Ant Design controls, leaving several inputs without usable accessible names.

**Verdict**: NEEDS_CHANGES

## High-level view

Customer type selection still determines the pricing target and clears resolved lines when the audience changes. Dealer browsing requires a selected registered customer; walk-in browsing now requires `customer.name.trim()`.

`QuotationProductBrowser` receives the target, quotation date, pricing label, existing product IDs, close callback, and multi-product completion callback. Added products enter the existing preview pipeline, while quantity, override rate, rate restoration, removal, line totals, and summary totals remain server-driven.

Creation still performs a final authoritative preview before submitting minimal line data. The standard footer calls the same submit handler and reflects `submitting`; Cancel and the modal close affordance call the same full reset path.

The new visible field labels are detached from their controls. **[confirmed]** This removes the old implicit date-label association and charge names supplied by `addonBefore`, so keyboard and assistive-technology users cannot reliably identify or focus several controls.

## Customer target gates the product browser

Dealer-type changes and dealer selection invalidate existing lines and close the browser before changing the target. Walk-in browsing is disabled until the customer name is nonblank, dealer browsing is disabled until `selectedDealer._id` exists, and submission enforces the same prerequisites.

The browser receives `target`, `pricingDate`, `pricingLabel`, and `alreadySelected`, and returns selected products through `onDone`. The completion callback closes the browser, excludes existing IDs, appends the new rows, and previews the complete line set.

## Authoritative edits, totals, and creation remain connected

Quantity edits, manual overrides, restoring the server rate, removals, charge changes, quotation-date changes, and walk-in customer changes still trigger authoritative repricing. Subtotal, discount, tax, and grand total still come from the response summary, with line totals retained as the existing grand-total fallback.

Create validates the target and nonempty items, awaits a fresh preview, and sends `minimalItems(pricedItems)` to `createQuotation`. The footer primary button exposes that handler with Ant Design's loading state; success still calls `onSuccess`, resets modal state, and closes.

## Detached visual labels leave ERP fields unnamed

**Medium — [confirmed].** The new `<label>` elements at `src/pages/sales/AuthoritativeQuotationModal.jsx:356-379` and `:410-443` neither wrap their controls nor provide matching `htmlFor`/`id` attributes. This is regressive for the date and charge fields: the old date labels wrapped their inputs, and the old charge inputs used descriptive `addonBefore` content. Use `Form.Item` labels or stable control IDs with matching `htmlFor` values, and provide the `Select` an equivalent accessible label, so clicking labels focuses fields and assistive technology announces their purpose.

</details>
